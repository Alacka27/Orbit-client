# Orbit — Minecraft 1.21.11 / Fabric

## 0.4.14 — визуальный этап 4 и внутреннее управление

- **FreeLook и Zoom теперь встроенные действия, а не модули.** Их нет среди карточек и в списке включённых функций; выключить их флагом старого конфига нельзя. FreeLook работает при удержании **LAlt в третьем лице**, Zoom — при удержании **C**. Колесо во время Zoom меняет приближение, а не слот; сохранённый FOV Minecraft не изменяется.
- **Ни одного действия Orbit в Minecraft → Управление → Назначение клавиш, включая «Разное».** Открытие меню, FreeLook, Zoom, ElytraSwap и все модульные бинды настраиваются только в **RShift → Settings → Управление Orbit**. Исходные клавиши: RShift / LAlt / C / G; остальные действия без бинда. «По умолчанию» возвращает внутреннее значение Orbit, а не настройку Minecraft. Старые строки `key.orbit.*` в `options.txt` не регистрируют клавиш и больше не используются.
- ПКМ по карточке открывает настройки модуля и его бинд. Обязательные действия открытия меню, FreeLook и Zoom нельзя оставить без клавиши. Клавишу открытия Orbit нельзя одновременно назначить модулю; обычные совпадения между модулями показываются предупреждением. Minecraft может использовать ту же физическую клавишу для своего обычного действия — это не скрытое переназначение его настроек.
- **Visual → TargetHUD:** имя/скин, дистанция, броня и доступное здоровье цели. У мобов — синхронизированное HP. У другого игрока используются только баллы отображаемого сервером scoreboard в формате **сердец (`HEARTS`)**, с подписью `scoreboard` и без придуманного максимума. Сам критерий `health` по vanilla-протоколу не передаётся: это заявленные сервером баллы здоровья, а не доступ к скрытому HP. Обычный числовой scoreboard не считается здоровьем. Без подходящего источника — «HP: нет данных», без выдуманной полоски 20/20.
- **DamageNumbers / HitParticles / CriticalHitEffect:** числа реального изменения доступного HP, зелёное лечение, частицы полученного урона и золотой эффект штатного критического события. Это только визуал: модуль не создаёт атаки, урон или критические удары.
- **ShieldStatus:** свой щит — удержание/блок, реальная прочность и собственный кулдаун. У других — видимый щит, блок и замеченное событие отключения; их прочность и скрытый таймер не угадываются.
- **TotemCounter:** точное число собственных тотемов в инвентаре и отдельное число замеченных срабатываний. Для других игроков — только наблюдавшиеся срабатывания, **не остаток тотемов в закрытом инвентаре**. Историю можно сбросить в настройках; смена мира/профиля очищает её.
- **SeeInvisibles:** полупрозрачное отображение уже известных клиенту невидимых игроков с обычной проверкой глубины. Мобы включаются отдельно. Невидимость самой сущности не снимается; неизвестные клиенту сущности и просмотр через стены не добавляются.
- **Trajectories доработан без дубликата:** градиент по времени полёта, метка первого столкновения и время до него; натяжение лука, заряженный стрелами арбалет, до трёх стрел Multishot, бросаемый трезубец. Снежки/яйца/жемчуг/зелья сохранены. Случайный разброс, фейерверки арбалета, Riptide, серверные плагины и отражения не моделируются.
- Все семь новых визуальных модулей **OFF по умолчанию**, параметры и бинды сохраняются по UUID и входят в именованные конфиги. TargetHUD и панель щита/тотемов можно перетаскивать через чат, как прежние плашки. Облака, логотип и оба шрифта сохранены.

**Установка:** убери старый Orbit из `mods`, оставь только `orbit-0.4.14-visual-stage4.jar`. Нужны Minecraft **1.21.11**, Fabric Loader **0.20.1+**, Fabric API **0.141.6+1.21.11**, Java **21+**. ZIP исходников — резервная копия, не мод.

Проверки и честные ограничения: [docs/QA_0.4.14_stage4.md](docs/QA_0.4.14_stage4.md). Этап 3 с взрывными модулями пропущен по запросу; остаток этапа 2.2 не объявляется выполненным. Авторизация и алгоритмы существующих атак/обмена предметов не расширялись.

> Ниже — история выпусков. Старые способы переназначения клавиш и выключения FreeLook/Zoom относятся только к указанным старым версиям; в 0.4.14 всё управление Orbit находится внутри Orbit.

## 0.4.13 — Zoom, бинды и жирный HUD

- **Zoom: удерживай C**, колёсиком меняй приближение, отпусти — камера плавно вернётся. Начальное приближение 3×, диапазон колёсика 1.25–30×. Во время удержания колесо не меняет слот хотбара; чувствительность поворота уменьшается пропорционально зуму. Сохранённая настройка FOV Minecraft не изменяется.
- **RShift → General → Zoom** включает или отключает функцию. В чате, меню, паузе, после смерти и без фокуса зум не действует. После возврата из меню или потери фокуса удерживаемую клавишу нужно отпустить перед новым приближением.
- **ПКМ по любой из 11 функций → «Бинд» → «Клавиша» → нажми клавишу или кнопку мыши → «Сохранить».** Доступны «Без бинда», «По умолчанию» и отмена без сохранения. Бинды сохраняются по UUID профиля и входят в именованные конфиги.
- FreeLook и Zoom используют **удержание**. ElytraSwap выполняет **один обмен по нажатию**, только когда его модуль включён. Остальные модули включаются/выключаются нажатием; повтор клавиши при удержании не переключает их многократно.
- Без личного переопределения FreeLook, Zoom и ElytraSwap используют клавиши из «Управления» Minecraft: исходно LAlt, C и G. «По умолчанию» возвращает именно эти стандартные настройки. Остальные модули исходно без бинда. Клавиша открытия Orbit зарезервирована; совпадения между модулями показываются предупреждением и действуют вместе. Обычное назначение этой же клавиши в Minecraft не отменяется.
- Плашка **ORBIT / FPS / пинг** использует настоящий **Orbit UI Bold, вес 700**, а не повторную отрисовку обычного текста. Ширина плашки считается по тому же жирному шрифту; координаты и остальной HUD не менялись.

Файл: `orbit-0.4.13-zoom-binds.jar`. В `mods` оставь **только одну версию Orbit**. Архив `sources.zip` — исходники, не мод. На GitHub не публиковалось. Этап 3 не начат; логика атак, обмена предметов и авторизации не расширялась.

Проверки и ограничения: `docs/QA_0.4.13_zoom_binds.md`.

## 0.4.10 — аккаунты без перезапуска

- **Profiles → offline-ник → «Применить»**: имя и UUID меняются без закрытия Minecraft. Сначала выйди из мира/сервера. Возврат к исходному аккаунту лаунчера — первая строка → «Применить».
- `+ Аккаунт` открывает Offline, Ely.by и Microsoft. Смена официального имени Minecraft этим экраном не выполняется; вход использует имя, выданное провайдером.
- Ely.by: e-mail/ник, пароль и необязательный код 2FA. Предназначен для серверов, поддерживающих авторизацию Ely.by. Ключ проверки Ely-скинов изолирован от ключей Mojang.
- Microsoft: официальный вход через браузер и одноразовый код. **В Orbit не встроен чужой Client ID.** Нужен собственный ID публичного приложения, одобренного для Minecraft API. Без настройки кнопка получения кода неактивна; готовность реального Microsoft-входа без одобрения не заявляется.
- **Пароли и онлайн-токены не записываются на диск.** Онлайн-сессии доступны только до закрытия игры; после перезапуска войди повторно. На диск сохраняются только offline-ники, обычные настройки и публичный Microsoft Client ID.
- При переключении обновляются службы сессии, профиль, скины, настройки по UUID, социальный/отчётный контекст, ключи чата и данные Realms. Учётные данные Ely.by не отправляются сервисам Microsoft. Заголовки серверных ресурспаков используют текущий ник/UUID.
- Кнопки регистрации открывают официальные сайты. Orbit не создаёт учётные записи автоматически и не заменяет покупку/право на Minecraft Java Edition.
- Все прежние функции 0.4.9 сохранены. Установка: оставь в `mods` только `orbit-0.4.10-accounts.jar`; полный ZIP исходников в `mods` не помещать.

Подробности и настройка: `docs/ACCOUNTS.md`. Фактические проверки и ограничения: `docs/QA_0.4.10_accounts.md`.

## 0.4.9 — предметы, этап 2.1 (тестовая сборка)

- **AutoTotem:** обычный обмен тотема из основного инвентаря/хотбара в левую руку. Вытесненный предмет возвращается в исходный слот. Можно задать порог HP с поглощением, порядок поиска и задержку.
- **AutoArmor:** по одному улучшению за задержку. Оценка учитывает броню, твёрдость, обычную Защиту (отключаемо) и прочность при равенстве. Это общая эвристика, не оптимизация под каждый тип урона. Надетые элитры и броню с Проклятием привязки не снимает.
- **AutoConsume:** ПКМ открывает отдельные AutoEat / AutoPotion / AutoGapple, SafeOnly, пороги и прерывание при уроне. Использует **только хотбар**, обычную еду, питьевые полезные зелья и золотые яблоки; не бросает взрывные/оседающие зелья. Зелья и яблоки дополнительно OFF по умолчанию. SafeOnly по умолчанию не начинает/прерывает использование при противнике в радиусе 8 блоков.
- **ElytraSwap:** включи модуль и нажми **G** для обмена элитр и нагрудника. Переназначение — стандартное «Управление» Minecraft. Только по нажатию, без автоматического срабатывания при падении. По умолчанию не снимает элитры в полёте.
- **RShift → Pvp → следующая страница:** четыре новых модуля. Все OFF по умолчанию. ЛКМ — включение, ПКМ/`...` — настройки; «Сохранить» применяет только выбранный модуль, Esc отменяет черновик.
- Один полный обмен предметов за клиентский тик; экстренный тотем имеет приоритет, автоматические атаки на время обмена/потребления приостановлены. Предметы не выбрасываются. При открытом меню/чате/контейнере, занятом курсоре, смерти или потере фокуса автоматика не действует.
- При завершении/отмене автопотребления восстанавливается прежний слот, **только если игрок сам не сменил слот**. Искусственное удержание использования снимается; настоящий ручной ввод не перехватывается.
- Исправление двойного blur из 0.4.8 hotfix1 сохранено; проверка JAR охватывает оба окна настроек. Облака, логотип, шрифты сохранены побайтно; в переводах только добавлена клавиша G. Старые профили и именованные конфиги совместимы, новые флаги в них OFF.
- **Это 2.1, не весь второй этап:** AutoBlock, ShiftTab, SafeWalk и TargetStrafe остаются на 2.2. Нет новых обходов античита и обещания работы на любом сервере.
- Файл: `orbit-0.4.9-items-stage2a.jar`. В `mods` оставлять только одну версию Orbit. Полный ZIP исходников — для резервной копии, не для `mods`. На GitHub без отдельного разрешения не публикуется.

Проверки и ограничения: `docs/QA_0.4.9_stage2a.md`.

## 0.4.8 — PvP, этап 1 (тестовая сборка)

- **KillAura / AttackAura:** обычное видимое наведение, плавный/мгновенный поворот или без поворота; приоритет по дистанции, углу либо HP мобов. Цикл из 1–5 целей, один удар за готовый кулдаун.
- **TriggerBot:** цель под прицелом; режим 1.9+ по кулдауну либо 1.8/CPS, 1–20 попыток атаки в секунду. CPS не меняет серверную механику боя.
- **RShift → Pvp:** ЛКМ включает модуль, ПКМ по карточке или кнопка `...` открывает настройки. Изменения параметров применяются кнопкой «Сохранить»; Esc/«Отмена» отменяют черновик. Положение окна сохраняется отдельно.
- Оба новых модуля **выключены по умолчанию**. По умолчанию выбираются игроки и требуется оружие. Для одиночного теста выбери «Цели: Мобы» и возьми меч.
- Общий обработчик не допускает двух модульных атак за один клиентский тик. При открытом меню/чате, смерти, режиме наблюдателя или потере фокуса атаки приостановлены. Пауза при использовании еды/щита включена по умолчанию.
- Параметр дальности 1–6 дополнительно ограничен штатной дальностью оружия Minecraft 1.21.11. Это **не Reach**. Через блоки не атакует; неполный поворот не выдаётся за попадание.
- У игроков не выдумываются HP: приоритет HP использует данные мобов, а неизвестные значения сортируются после известных, далее по расстоянию.
- Копья с отдельной piercing/kinetic-механикой в этом этапе не поддерживаются. Нет FT/GRIM, silent rotations и обещаний обхода античита.
- Настройки сохраняются по профилю и входят в именованные конфиги. Старые конфиги загружаются с новыми модулями OFF.

Стабильный JAR 0.4.7 оставлен отдельно. Эта версия предназначена для проверки, не для заявления совместимости с любым сервером.

Подробности: `docs/QA_0.4.8.md`, восстановление базы: `docs/RECOVERY_0.4.7.md`.



## 0.4.6-violet-ui — Violet Glass в игре

Утверждённый стиль макетов перенесён в рабочее оформление Minecraft: прежние облака, фиолетовый акцент, светлый текст, градиентное стекло, мягкие рамки и единые скругления.

- Главное меню: исходные действия Minecraft, белая планета, ник/реальная голова рядом с **Profiles**. RShift: карточки и настоящие переключатели FreeLook, NoFall, Jesus, Trajectories, пустая Fun без фиктивных функций. В паузу добавлена кнопка **Меню Orbit**; стандартные действия, включая серверные диалоги, сохраняются.
- **Profiles**: список с аватарами, выбранной и текущей учётной записью, прокруткой/страницами, добавлением/переименованием/удалением. Это прежние offline-профили и аккаунт лаунчера; выбор применяется **после перезапуска**. Авторизация Microsoft/Ely.by не добавлялась.
- **Интерфейс**: HEX/RGB, прозрачность, анимации, цветовые образцы, живой предпросмотр, Применить/Сбросить/Назад. Сохранённые личные настройки не перезаписываются при обновлении; **Сбросить → Применить** включает новый фиолетовый пресет. Данные входа не меняются.
- **HUD**: стеклянные хотбар/вторая рука, крупные ячейки, фиолетовые выбор и XP; сердца, броня, голод, атака и управление остаются штатными. Масштабируется вся нижняя группа вместе, а не только фон. Плашки FPS/пинга/XYZ используют реальные значения; в одиночной игре написано Singleplayer. F1 скрывает HUD, F3 убирает дополнительные плашки.

## FreeLook — сохранён из версии 0.2.0

**Написаны FreeLook и новое главное меню. Полный клиент из плана ещё не готов.**
Согласованные требования: [docs/PLAN.md](docs/PLAN.md).

### Что делает новая реализация

- В виде **от третьего лица со спины** (первое нажатие F5 из первого лица) удерживай **левый Alt**, чтобы вращать камеру, не меняя направление взгляда/движения персонажа мышью.
- При отпускании Alt камера плавно возвращается за спину. Во время возврата обычное управление мышью снова работает.
- Камерные углы изменяются до стандартного расчёта положения камеры: ванильное ограничение камеры стенами остаётся в цепочке.
- В первом лице, во фронтальном F5, в меню, при потере фокуса, смерти или смене мира FreeLook сбрасывается. После сброса сначала отпусти клавишу и зажми заново.
- Клавиша переназначается в **Настройки → Управление → Назначение клавиш → Разное → Orbit: свободный обзор (удерживать)**. Minecraft сохраняет её в своих настройках.
- В версии 0.3.1 используется общая строка инициализации меню и FreeLook, указанная выше.

Это описание реализации, а не подтверждение теста в Minecraft. Компиляция и применение Mixin требуют проверки нового запуска Actions и игры.

### Сохранение настроек

При первом запуске создаётся `config/orbit/freelook.properties`:

```properties
enabled=true
returnSpeed=12.0
```

`returnSpeed` — скорость возврата в диапазоне **1–40**: больше = быстрее. Меняй при закрытой игре; файл читается при запуске. Неверный файл не перезаписывается: функция отключается, ошибка записывается в журнал. Собственного экрана настроек пока нет.

**Ещё НЕ реализованы:** смена офлайн-сессии без перезапуска, вход Microsoft/Ely.by, баланс, профили Singleplayer/Multiplayer, Baritone, Freecam, ESP и остальные модули из плана.

## Сборка и установка

Актуальная версия — 0.4.14. Исходники/ZIP и готовый мод — разные файлы. Локальная и GitHub-сборка используют одинаковые исходные ресурсы; игровые проверки описаны отдельно от CI.

1. Закрой игру. Перемести старый Orbit JAR в запасную папку **вне `mods`** и положи выданный `orbit-0.4.14-visual-stage4.jar` в `mods`. Одновременно оставляй только одну версию Orbit.
2. Используй Minecraft **1.21.11**, Fabric Loader **0.20.1+**, Fabric API **0.141.6+1.21.11** и совместимую Java 21+.
3. Первый тест проведи в отдельном одиночном мире, сначала без дополнительных модов. Проверки новой версии — `docs/QA_0.4.14_stage4.md`. Затем отдельно проверь с Sodium подходящей версии; совместимость с ним этим выпуском не подтверждена.

Для сборки из архива исходников нужны JDK 25, Gradle 9.8.2 и Python 3: выполни `gradle --no-daemon build` из корня проекта. Готовый JAR появится в `build/libs`. Самостоятельные тесты запускаются отдельно, например `bash scripts/test-combat.sh`; для полного прогона запусти каждый скрипт `scripts/test-*.sh`.

Workflow **Actions → Orbit - Fabric build** собирает исходники выбранной ветки; ожидаемое имя артефакта — `orbit-1.21.11-0.4.14-visual-stage4`. Резервная ветка `save/0.4.14-stage4` не запускает push-триггер для `main`; запуск вручную и зелёный статус Actions не являются игровым тестом.

Если запуск Actions красный, пришли блок `What went wrong` или ошибки `compileClientJava`. При краше Minecraft — ошибку `Mixin`/`Caused by` из `logs/latest.log` или краш-репорт, скрыв личные данные.

Если автоматического запуска нет: **Run workflow → выбери нужную ветку → Run workflow**. **Re-run** старого запуска повторяет старый коммит, а не новые исходники.

## Чек-лист в игре

- Игра запускается, в логе новая версия Orbit; в назначениях клавиш Minecraft **нет ни одного действия Orbit**.
- F5 со спины → удерживать W, затем Alt → двигать мышью влево/вправо: путь персонажа не должен поворачиваться за камерой.
- То же со спринтом и прыжками; вверх/вниз без переворота камеры.
- Отпустить Alt: возврат за спину без поворота персонажа; снова работает обычная мышь.
- Быстро повторно зажать Alt во время возврата: камера не должна резко перескакивать.
- Esc, Alt-Tab, смена F5, смерть/возрождение, выход и повторный вход: никаких застрявших углов или ввода; для повторной активации отпустить Alt и зажать снова.
- Проверить переназначение клавиш только в Orbit → Settings → Управление Orbit и загрузку изменённого `returnSpeed` после перезапуска.
- Сравнить поведение при низком и высоком FPS; не атаковать/строить, ориентируясь по свободной камере: направление взаимодействий остаётся направлением персонажа.

## Что проверено

- Основа 0.1.0-bootstrap ранее собрана и запущена пользователем с Fabric 1.21.11 / Java 21; в журнале есть инициализация и вход в одиночный мир.
- Для новой реализации есть независимые Java-тесты вращения, ограничений pitch, плавного возврата, повторного удержания, независимости от частоты кадров и сохранности конфигов.
- Тесты запускаются командой `bash scripts/test-freelook.sh` без Minecraft-зависимостей. Они НЕ проверяют применение миксинов, потерю фокуса в настоящем окне и визуальный результат.
- Состояние новой сборки Actions и тест в игре следует подтверждать отдельно; наличие исходников не означает, что проверка уже прошла.

## Технические зависимости

Версии основы взяты из официального `FabricMC/fabric-example-mod`, ветка `1.21.11`, commit `8272aadc8605a4661685465c22f80aab21c7b969`:

- Minecraft 1.21.11; Fabric Loader 0.20.1; Fabric API 0.141.6+1.21.11.
- Loom 1.19-SNAPSHOT; Gradle 9.8.2.
- **JDK 25 для Gradle/Loom**, целевой байткод собственного мода **Java 21**.
- MixinExtras используется из Fabric Loader; отдельный мод для него не требуется. Клиентские миксины объявлены с `JAVA_21` и `defaultRequire: 1`: несовпадение точки внедрения не должно молча скрываться.

Loom остаётся upstream SNAPSHOT, поэтому полностью воспроизводимая сборка пока не гарантирована. Первая сборка требует загрузки зависимостей из сети; с заранее подготовленным кэшем проверена локальная сборка `gradle --no-daemon --offline build`.

Локальная сборка при установленном Gradle 9.8.2, JDK 25 и Python 3: `gradle --no-daemon build`. Gradle автоматически восстанавливает исходные PNG-иконку/облака, оба шрифта и закреплённый публичный ключ Ely из проверяемых текстовых источников; внешние Python-пакеты не требуются. Поэтому текстовая резервная копия GitHub собирается без локальных бинарных ресурсов. Если Python вызывается командой `python`, добавь `-PpythonExecutable=python`. Gradle Wrapper пока не добавлен.

В репозиторий не включаются файлы Minecraft, секреты, токены или сторонний Baritone JAR. Baritone не подключён. Google Диск на этом этапе не изменяется.

## Замена логотипа в 0.3.1

Использована присланная картинка: чёрные поля обрезаны, чёрный фон заменён прозрачностью, белая форма и обе звезды сохранены. Подготовленный логотип 512×512 хранится как `tools/assets/orbit-logo.png.b64` и восстанавливается при сборке без внешних Python-пакетов. Это логотип главного меню и иконка мода, не аватар аккаунта и не значок отдельного лаунчера. Синяя тема, кнопки и FreeLook не менялись. Новая сборка и запуск требуют проверки Actions и Minecraft.

Новые ресурсы `clouds.png` генерируются Python-скриптом из исходного дизайна. Для новой сборки Actions проверяет наличие фонового PNG и обоих новых клиентских mixin-классов. Google Диск не изменялся.

# Orbit — согласованный план

Статус: требования согласованы; реализация и сборка ещё не выполнены.
Цель: Minecraft Java Edition 1.21.11, Fabric. До разработки необходимо проверить версии Fabric Loader, mappings, Loom, Fabric API, Gradle и совместимость Baritone. Наличие этого файла не означает, что клиент уже работает.

## Подтверждённые требования

- FreeLook в третьем лице при удержании Alt: камера вращается независимо от направления персонажа; после отпускания плавно возвращается за спину.
- Навигация через совместимый Baritone: #go x z / #go x y z, #stop, #pause, #resume; разрешены ходьба, бег, плавание, разрушение и установка блоков. Не заявлять интеграцию готовой без проверки зависимости.
- Ручная настройка темы: цвета, прозрачность и анимации; именованные сохраняемые конфиги. Без готовых пресетов тем.
- ClickGUI на правый Shift; ник и голова скина. Баланс только из доступного серверного источника, например scoreboard; при отсутствии данных — «Недоступен».
- Переключаемые профили Singleplayer / Multiplayer в главном меню: отдельные конфиги одного мода, не замена jar во время работы.
- Менеджер клавиш и Panic Button.

## Запрошенные модули: backlog, не готовые функции

Visual: собственное главное меню, watermark/version, splash-тексты, ViewModel (положение, поворот, прозрачность, свечение), RainbowUI, контуры блоков и оформление HUD.

Обзор/инструменты: X-Ray; ESP Player/Mob/Item/Storage; Tracers; Nametags (здоровье, дистанция, броня); Freecam отдельно от FreeLook; Fullbright; Jesus; NoFall; Trajectories; AutoTool; ItemScroller; InventoryPlus/XCarry; SeeInvisibles.

PvP: KillAura; AutoTotem; CrystalAura; SafeWalk; Surround; Velocity; Criticals; Reach; AutoArmor; TargetStrafe.

HUD: счётчики PvP-предметов, предупреждения о низких запасах, ArmorHUD, TargetHUD, координаты, скорость, FPS.

Дополнительно: AutoPotion, AutoEat, AutoSneak при атаке, ElytraSwap/FastSwap, AutoRespawn, AutoReconnect с задержкой и ограничением попыток; Zoom; метки точек и последней смерти.

## Ограничения и проверка

- Серверные проверки определяют действие Reach, Velocity, NoFall, Jesus, Criticals, XCarry и других модулей. Универсальная работа и отсутствие банов не обещаются.
- SeeInvisibles/ESP доступны только для данных, переданных клиенту. Баланс нельзя выдумывать или получать из закрытых данных.
- «NoServerDesync» требует конкретного воспроизводимого сценария; не обещать универсальное устранение рассинхронизации.
- Не выдавать заглушки за реализованные модули. Для каждой функции отдельно фиксировать: реализована, собрана, проверена в игре.
- Сначала проверка зависимостей и минимальная сборка, затем камера/конфиги/UI, далее модули по этапам.
- Успешная сборка jar не равна проверке в Minecraft. Финальный релиз требует запуска и тестирования.

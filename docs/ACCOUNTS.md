# Аккаунты Orbit 0.4.10

## Сменить offline-ник без перезапуска

1. Выйди из одиночного мира или сервера и дождись главного меню.
2. Открой **Profiles**. Введи ник из 3–16 латинских букв, цифр или `_` и нажми **Добавить**.
3. Выбери строку и нажми **Применить**. Закрывать игру/лаунчер не нужно.
4. Для возврата выбери первую строку **Launcher** и нажми **Применить**.

Это реальная смена клиентского профиля/UUID, не косметическая надпись. Нельзя сменить личность уже подключённого игрока, не покинув мир/сервер. Offline-ник не переименовывает официальный аккаунт и не позволяет войти на сервер с проверкой лицензии. На offline-серверах другой ник/UUID может означать другой инвентарь, права и прогресс; это определяется сервером.

Offline-список совместим с прежним `config/orbit/profiles.properties`. Выбранный offline-ник повторно применяется, когда следующий запуск достигает обычного главного меню. Запуск Quick Play в обход меню не заявлен как поддерживаемый для автопереключения. Исходная сессия лаунчера сохраняется отдельно в памяти, даже если на старте выбран offline-профиль.

## Ely.by

**Profiles → + Аккаунт → Ely.by.** Введи e-mail/ник, пароль, при необходимости текущий шестизначный код 2FA и нажми **Войти и применить**. После сообщения о 2FA пароль вводится повторно: поле очищается при отправке. Регистрация открывается на официальном сайте Ely.by.

Вход и обновление токена используют документированный API `https://authserver.ely.by/auth/...`. Соединение с Ely-сервером подтверждается через `/session/join`, а не через Mojang. Для этого сервер должен поддерживать Ely.by. Обычная Microsoft-only проверка лицензии не примет Ely-аккаунт.

Скины Ely обрабатываются отдельным провайдером с публичным ключом Ely, без отключения проверки подписи Mojang. Ключ взят из `https://skinsystem.ely.by/signature-verification-key.der`, SHA-256 `37b6c5f379f8538e74a8750b51273d11051e758be0205b1ea71e4fd88aba1ce0`. Некорректная/неизвестная подпись, недоступность профиля или неподдерживаемый URL текстуры дают стандартный скин, а не глобальное доверие любому скину. Плейсхолдер `Cg==` не считается проверенной подписью.

Удаление неактивной Ely-сессии из списка инвалидирует только токен этой сессии Orbit. API `/auth/signout`, завершающий все входы пользователя, не используется. Сначала переключись на другой аккаунт, если удаляемая сессия активна.

Документация: https://docs.ely.by/en/minecraft-auth.html и https://docs.ely.by/en/skins-system.html.

## Microsoft — требуется настройка приложения

**Без Client ID кнопка получения кода специально неактивна. Это не готовый общедоступный OAuth-сервис Orbit.** Для своей публичной desktop/device-code интеграции разработчику нужен зарегистрированный Microsoft application/client ID и разрешение на использование Minecraft API.

1. Зарегистрируй собственное приложение в Microsoft Entra с поддержкой личных Microsoft-аккаунтов; разреши публичный client/device-code flow. Используется tenant `consumers` и scope `XboxLive.signin offline_access`.
2. Запроси необходимое разрешение Minecraft API: https://aka.ms/mce-reviewappid. Наличие Client ID само по себе не означает, что это разрешение уже получено. Срок одобрения Orbit не контролирует.
3. В **Profiles → + Аккаунт → Microsoft** введи одобренный Client ID. Это публичный идентификатор, не пароль. Client secret не нужен и в JAR не встраивается.
4. Нажми **Получить код входа**, затем **Открыть Microsoft**. Введи показанный код на официальном сайте и выполни вход в своём браузере. Пароль Microsoft никогда не запрашивается в Orbit.
5. После подтверждения выполняются Microsoft → Xbox Live → XSTS → Minecraft, проверка права на Java Edition, загрузка настоящего профиля и разрешений аккаунта. Родительские ограничения/ошибки Xbox не заменяются разрешающими offline-настройками.

Официальное имя берётся из профиля Minecraft; поле offline-ника к нему не применяется. Если профиля ещё нет, сначала настрой Minecraft Java в официальном лаунчере. Регистрация Microsoft сама по себе не предоставляет право на игру.

Кнопки **Отмена**, **Заново** и выход с экрана отменяют ожидание и запрещают позднему ответу применить сессию. `authorization_pending`, `slow_down`, истечение кода, отклонение входа и HTTP 403 приложения обрабатываются отдельно. Ссылки входа принимаются только с известных HTTPS-доменов Microsoft.

Документация: https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code и https://minecraft.wiki/w/Microsoft_authentication.

## Хранение и изоляция

- На диске: offline-ники, выбранный режим следующего запуска, публичный Microsoft Client ID, обычные настройки по UUID, публичные кэши имён/скинов.
- Только в оперативной памяти текущего процесса: онлайн-сессии, access/refresh/client-токены, введённые пароль/2FA на время входа. После закрытия Minecraft потребуется повторный вход в добавленный Ely/Microsoft-аккаунт. Автоматическое сохранение секретов/«запомнить пароль» не реализовано.
- Штатные кэши Minecraft не отключаются. В частности, официальный менеджер подписанных ключей чата может записывать ключи в `profilekeys/`; это отдельный механизм Minecraft, не сохранение пароля или access/refresh-токена Orbit.
- Поля пароля маскируются; текст пароля исключён из narration и копирования/вырезания. Поля очищаются после отправки/выхода с экрана. JVM использует строки; гарантированное физическое обнуление всех копий в куче не заявляется.
- Запросы ограничены HTTPS-адресами нужных провайдеров, не следуют HTTP-редиректам, имеют тайм-ауты и ограничение размера ответа. Пароль Ely не отправляется Microsoft, токены Microsoft не отправляются Ely. Сырые ответы сервисов не выводятся в сообщения об ошибке/логи Orbit.
- Ключи подписи чата, User API, профиль, скины, социальный/отчётный контекст, telemetry и Realms относятся к выбранной сессии. Ely/offline не получают ключи Microsoft, доступ к Realms или telemetry Microsoft.
- Восстановление Launcher сохраняет исходный объект пользователя и исходный auth-провайдер лаунчера, а не строит «официальный аккаунт» из одного имени.

## Проверка

`bash scripts/test-accounts.sh` использует только поддельные ответы транспорта и не выполняет настоящую авторизацию. `bash scripts/test-account-skins.sh` дополнительно проверяет синтетические RSA-подписи текстур, изоляцию Ely session endpoints и обработку ответов HTTP. Оба сценария требуют библиотек из Gradle-кэша, поэтому сначала выполни обычную сборку. Подробности локального запуска — в `QA_0.4.10_accounts.md`. Без реальных аккаунтов, одобренного приложения и соответствующего сервера нельзя заявить полный end-to-end тест Ely/Microsoft.
